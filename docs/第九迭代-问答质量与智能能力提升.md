# 第九迭代：问答质量与智能能力提升

## 已实现范围

- 同一会话最近 8 条已完成消息作为上下文，用于理解“它、继续、按刚才口径”等追问。
- 上下文只用于理解意图，最终答案仍必须依据本次真实查询结果和知识库证据。
- 新会话中“看看、查一下、继续”等明显缺少分析条件的问题会进入澄清，不执行数据源查询。
- MySQL 或 Elasticsearch 查询执行失败时，模型可根据真实错误、结构和授权范围自动修正一次；修正后仍需经过 SQL/DSL 安全校验。
- 任务记录 `retry_count` 和 `clarification_requested`，执行过程展示“修正查询”和“等待补充条件”。
- 用户可以对完成回答提交“有帮助”或“需改进”，后者支持 500 字原因说明。
- 管理员“问答质量”页面支持维护固定评测问题、数据源类型及预期关键词。
- 评测任务复用真实模型、数据源、安全网关和问答任务链路，按答案与查询中的关键词命中率自动评分。
- 质量页面汇总用户反馈、评测次数、平均命中率和最近运行结果。

## 数据结构

Flyway V9 增加：

- `chat_message.feedback_rating/feedback_comment/feedback_at`
- `analysis_task.retry_count/clarification_requested/evaluation_case_id`
- `evaluation_case`
- `evaluation_run`

## 手动验收

1. 重启后端，确认 Flyway 升级到 V9。
2. 在新会话只输入“看看”，确认系统要求补充指标、时间范围和筛选条件，且没有 SQL/DSL。
3. 提问一个完整问题，得到回答后继续输入“按天展示趋势”，确认生成的查询继承前一轮主题和条件。
4. 使用测试数据源制造一次可修正的字段或语法错误，确认执行过程出现“根据执行错误修正查询”，且最多重试一次。
5. 对答案点击“有帮助”和“需改进”，刷新后确认反馈状态保留。
6. 管理员进入“问答质量”，创建 MySQL 或 Elasticsearch 用例并填写预期关键词。
7. 选择匹配类型的模型和数据源运行评测，确认状态变为 `COMPLETED` 并显示命中率。
8. 在“运行与审计”确认评测任务仍保留完整模型调用、查询和错误记录。

## 评测口径

当前自动分数为预期关键词命中率：命中的关键词数量除以用例配置的关键词总数，匹配范围包括最终答案和通过安全校验的实际 SQL/DSL。该分数适合持续回归和版本间对比，不代表完整的事实正确率。涉及关键业务结论的评测仍需要人工核查证据、查询口径和结果集。
