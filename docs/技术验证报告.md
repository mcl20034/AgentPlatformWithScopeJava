## 1. 验证范围与边界

本轮验证使用 Java 21 和 Maven 3.9.8 的独立路径执行，没有修改机器全局 Java 8 配置。部署方案按用户要求改为原生进程，不使用 Docker。对用户提供的 Elasticsearch 和 MySQL 只执行读取、mapping、聚合、过滤、权限查看和基础只读 SQL，没有创建、更新或删除业务数据。

模型协议测试使用本机 HTTP 夹具驱动真实 AgentScope 2.0.1 OpenAI/Ollama 适配器，证明请求格式、流式解析、工具调用、事件和错误处理的代码路径能够工作。它不等价于真实模型的能力和质量验证。

凭证未写入本报告、源代码或测试输出。临时连接配置存放在被 `.gitignore` 排除的 `.local/`，并设置为当前 Windows 用户专用 ACL。

## 3. 自动化验证结果

最终执行结果：21 个测试，18 个通过，0 个失败，3 个条件跳过。

- Spring Boot、Spring Security、Jackson、嵌入式 Web 容器和 SSE 同时启动及响应：通过。
- 中文 PDF 按页提取、DOCX 正文与表格读取、UTF-8 TXT 行定位、损坏 PDF 拒绝：通过。
- JSqlParser 识别 CTE、UNION 和子查询中的物理表，多语句与写语句区分：通过。`SELECT SLEEP(...)` 仍可被语法解析，证明必须另做函数白名单，不能把“可解析”当成安全。
- OpenAI 适配器非流式和流式工具调用、工具结果事件、Bearer 凭证和自定义 base URL：通过。
- Ollama 适配器非流式和流式工具调用及事件：通过。
- 不同模型版本的地址、模型名和凭证隔离：通过。
- 模型 500 错误在显式 `maxAttempts=1` 时不自动重试：通过。
- 显式超时预算和结构化输出 fallback 工具：通过。
- 并发会话与停止：实测同一个 ReActAgent 实例可以同时发出不同会话请求，和 2.0.1 源码中的线程安全注释不一致；`interrupt(context)` 不会立即解除正在等待的 HTTP 响应，应用层还必须取消 Reactor 订阅并依靠 HTTP/整体超时回收资源。

## 4. Elasticsearch 真实服务验证

验证服务版本为 9.0.2，验证索引为用户指定的两个 news 索引。以下只读链路通过：

- 服务连接和认证。
- 两个具体索引的 mapping 读取；没有使用通配符或多索引查询。
- `size: 0`、服务端 5 秒 timeout 的限量搜索；无超时、无失败分片。
- `match_none` 空结果语义。
- 日期字段的带时区范围过滤。
- 可聚合 keyword 字段的 `terms size: 3` 聚合，以及 `sum_other_doc_count` 截断信息读取。

发现一项需要进入产品校验器的兼容性规则：两个索引均存在类型为 `keyword`、但禁用 `doc_values` 的字段。对该字段做 terms 聚合会返回 400。因此管理员配置“可聚合字段”时，后端必须同时检查类型和 `doc_values`，连接测试也应实际执行无副作用的小型聚合。

尚未验证 ES 的分片失败、超时部分结果、cardinality 近似计数、100 桶总预算、多层聚合和拒绝非法 DSL。这些属于 SPIKE-04 后续项。

## 5. MySQL 真实服务验证

服务报告版本为 8.0.42。以下项目通过：

- JDBC 连接。
- 只读事务中的 `SELECT VERSION(), 1 + 1`。
- 5 秒 JDBC 查询超时配置。
- `SHOW GRANTS FOR CURRENT_USER()` 权限读取。

权限检查发现当前测试账号具有写入或管理类权限。它可以用于本轮连接探测，但不满足 PRD 的生产只读账号要求。正式联调前应创建仅允许目标数据库和目标表执行 SELECT 的专用账号；平台仍需保留 SQL AST 校验和超时限制。

由于尚未提供具体数据库名与允许查询的表，本轮没有读取 schema、表数据或执行真实聚合，也没有验证 `max_execution_time`、Statement.cancel、连接池回收和权限越界拒绝。它们属于 SPIKE-03 后续项。

## 6. PostgreSQL + pgvector

用户提供的 `kingbase` 服务实际为 KingbaseES V8，不是标准 PostgreSQL；只读探测时 `vector` 和 `kvector` 都未出现在可用扩展列表中。它不适合作为当前设计的 pgvector 验证目标。

用户决定稍后在自己的机器安装标准 PostgreSQL + pgvector，因此本轮按要求跳过。安装后需要补测：Flyway 迁移、事务表、无固定维度向量列、代次过滤、精确余弦检索、连接池与备份恢复。技术设计继续保留 PostgreSQL + pgvector，不改用现有业务 ES 存储知识库向量。

## 8. 对设计与开发的约束

1. 每个任务创建并释放独立 ReActAgent；平台自行约束单会话一个运行任务和全局 5 个任务。
2. 模型与工具执行都显式配置 timeout 和 `maxAttempts`，不能接受 AgentScope 默认模型重试次数。
3. 停止同时触发 AgentScope interrupt、Reactor subscription dispose、HTTP/JDBC 取消和整体截止时间；interrupt 不是资源已释放的证明。
4. ES 聚合字段必须检查 `doc_values`，并保存近似或截断元数据。
5. MySQL 必须换用专用只读账号，且仍采用 AST 白名单和数据库权限双重控制。
6. PostgreSQL + pgvector 安装完成前，文档知识库的持久化和检索链路不得标记完成。
