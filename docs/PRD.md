本文档作为后续产品设计、技术方案、开发任务拆分、测试与交付验收的统一依据。原始需求保留为背景材料；与本文档不一致时，以本文档为准。用户后续明确提出的变更，应先同步本文档和受影响的验收项，再调整实现。

用户已明确的需求包括：基于 AgentScope Java 建设平台；支持配置并选择 OpenAI、Ollama 模型；支持 MySQL、Elasticsearch 和上传文档作为数据源；展示“数据源 → 查询 → 证据 → 结论”；支持下载分析结果。

## 2. 产品定位与目标

面向内部业务人员的数据问答与分析平台。用户选择模型和已配置的数据源，用自然语言提问，获得有数据依据的回答，并能够查看执行步骤、追溯来源及下载结果。

第一版聚焦配置好的业务范围，不承诺接入任意数据库或文档后即可回答所有问题。平台负责让执行过程可见、业务口径可配置、答案依据可核查。

### 2.1 产品目标

1. 管理员无需修改代码即可维护多个模型和数据源。
2. 业务用户无需编写 SQL 或 ES 查询即可完成已支持场景的查询和分析。
3. 用户能分辨实际数据、分析结论、信息不足及执行失败。
4. 每次回答及下载报告保留足够的证据与执行信息，可供复核。

### 2.2 第一版不包含

- 跨数据库、跨 ES 索引、数据库与文档之间的联合分析。
- 数据写入、更新、删除、数据库结构变更及业务系统操作。
- 扫描件 OCR、图片理解、音视频解析、网页采集。
- 自动制作 Word、PDF、PPT 报告和可视化仪表盘。
- 多租户计费、组织权限树、企业单点登录、细粒度业务行列权限。
- 可视化智能体编排、自动训练模型、定时分析任务及自动发送报告。

## 3. 用户、权限与使用场景

### 3.1 用户角色

- 管理员：维护账号、模型、数据源、表及字段说明、指标口径、知识库文档；执行连接及能力测试。
- 普通用户：使用已启用的模型及数据源，管理自己的会话，查看执行过程，下载自己的结果。

第一版采用内部单组织部署和本地账号登录，不开放自主注册。所有普通用户共享管理员发布的数据源访问范围；只有适合该范围内所有用户查看的数据才可发布。会话和导出文件按账号隔离，管理员不默认获得其他用户的会话内容访问权。

### 3.2 典型场景

- MySQL：查询指定月份销售额，并按地区汇总；按照配置的订单状态、退款规则和时间字段计算。
- Elasticsearch：查询某时间段的错误记录，按错误类型聚合，给出计数及代表记录。
- 文档：在一个包含多个文档的知识库中查找某项制度，回答并引用对应文档段落。
- 复核：展开执行过程，查看实际查询、返回概况及来源，再下载报告和结构化查询结果。

## 4. 第一版范围与核心流程

第一版交付包含模型管理、数据源管理、文档知识库、对话问答、执行过程、会话历史、结果导出和基本登录权限，三类数据源均须具备可验收的完整流程。

### 4.1 核心流程

1. 管理员配置模型，完成连接和能力测试并启用。
2. 管理员配置数据库或 ES 数据源，维护业务说明并发布；或上传文档到知识库，等待处理完成。
3. 用户新建会话，选择一个模型及一个数据源。
4. 用户提问，平台检查数据源状态和问题信息；信息不足时先澄清。
5. 平台执行受约束的查询或文档检索，实时展示执行阶段与证据概况。
6. 平台基于实际结果生成回答，展示来源、口径和限制。
7. 用户继续追问、查看历史或下载结果。

### 4.2 数据源选择规则（SCOPE-01）

- 每个会话选择且仅选择一个数据源：一个 MySQL 数据库、一个具体 ES 索引，或一个文档知识库。
- 同一 MySQL 数据库内允许在授权表之间关联查询；关联关系需要配置或可验证。
- 同一知识库可包含多个文档，允许在库内综合检索。
- 首次发送问题后锁定模型和数据源；切换时新建会话，避免上下文混淆。
- 不提供自动切换模型、跨数据源补查或无数据依据的通用聊天模式。
- 第一版 ES 不接受通配符索引和多索引别名。

## 5. 功能需求

### 5.1 模型管理

**MODEL-01 配置与维护**

支持新增、编辑、启用、停用、连接测试和能力测试。字段包括：显示名称、提供方类型（OpenAI / Ollama）、服务地址、实际模型标识、API Key（服务需要时填写）、请求超时、备注。

显示名称用于用户选择，模型标识用于调用服务，两者必须分开。OpenAI 兼容服务仅在经过测试后纳入支持范围，不承诺所有兼容接口行为一致。

**MODEL-02 能力检测**

分别记录连接、基础对话、工具调用、流式响应测试结果及测试时间。可用于数据问答的模型必须通过基础对话及工具调用测试。流式响应不通过时允许一次性展示最终文本，但执行阶段仍需可见。修改地址、模型标识或密钥后使原测试结果失效，重新测试后方可启用。

密钥加密保存，页面仅展示掩码，不返回原文，不进入对话、普通日志和导出文件。连接测试成功不等于业务回答质量达标。

**MODEL-03 停用行为**

停用后禁止新请求使用，历史记录仍可查看和导出；已开始的请求使用其配置快照完成。涉及紧急终止时由用户停止任务，不能在后台静默替换模型。

### 5.2 MySQL 数据源

**MYSQL-01 配置与发布**

配置名称、主机、端口、数据库、只读账号及凭证，支持连接测试、读取元数据和手动刷新。管理员选择允许访问的表或视图，维护表用途、字段说明、关联关系及常用指标口径。

每项关键指标记录名称、计算规则、时间字段、过滤条件、单位及适用范围。例如销售额应说明是否扣除退款及包含哪些订单状态。管理员提供默认时区；默认值为 Asia/Shanghai。发布至少要求连接成功、选定表且填写业务用途。

**MYSQL-02 查询执行**

根据问题、授权结构和业务说明生成 SQL，经后端语法、权限和资源约束校验后执行。采用数据库只读权限及后端校验双重限制，不仅依靠提示词或字符串关键字判断。禁止多语句、写操作、DDL、文件操作、越权访问及有副作用的调用。

返回条数限制针对展示或导出的结果行，不能通过截断原始数据再计算总数等方式改变业务结果。统计与计算尽量由数据库完成。

**MYSQL-03 准确性与澄清**

未定义的关键业务口径、含糊的时间范围或无法确定的关联关系，先向用户澄清，不自行编造。查询出错时可以进行有限次数的修正；所有尝试都保留在执行记录中。空结果、NULL 和数值 0 应明确区分。

### 5.3 Elasticsearch 数据源

**ES-01 配置与发布**

配置名称、服务地址、认证信息及一个具体索引。支持连接测试、读取与刷新 mapping，配置字段用途、时间字段、时区、全文检索字段、可过滤字段及可聚合字段。

**ES-02 检索与聚合**

支持关键词检索、时间及字段过滤、排序和配置范围内的聚合。根据 mapping 使用适合的字段类型。生成的查询必须经后端校验，仅允许对配置索引执行受限搜索；禁止写入、索引管理、自定义脚本及访问其他索引。

明细结果和聚合结果分别保留，聚合桶数受限制。对于近似统计、桶截断或未获取全部命中记录的情况，必须展示限制，不能表述为精确全量结果。

### 5.4 文档知识库

**DOC-01 上传与状态**

管理员创建知识库并上传文本型 PDF、DOCX、TXT。默认单文件不超过 20 MB、单知识库最多 100 个有效文档；限制可配置。校验实际格式，拒绝空文件、损坏文件、加密且无法解析的文件及不支持的格式。扫描 PDF 缺少可提取文字时提示第一版不支持，不显示处理成功。

状态包括：待处理、处理中、可检索、处理失败、已移除。失败应展示可理解的原因并允许重试。仅可检索文档参与问答；知识库至少有一个可检索文档后才能被选择。有文档仍在处理时，提示其尚未纳入回答。

**DOC-02 解析、检索与引用**

处理流程包括文本解析、分段、建立检索索引及保存来源位置。第一版采用分段检索，并配置独立的嵌入模型；对话模型和嵌入模型配置分别管理，不要求两者为同一模型。嵌入模型默认支持经测试的 OpenAI 或 Ollama 接口，管理员需完成连接测试。

同一知识库使用一个嵌入配置版本。更换嵌入模型后必须重建索引，在新版本构建完成前保持旧版本可用，不混用不同模型的向量。重排序不是第一版必需项。

回答引用包含文档名称、文档版本、片段内容及定位信息：PDF 使用页码；DOCX 使用标题路径或段落编号；TXT 使用行号范围。不能把 DOCX 动态排版页码当作稳定定位依据。

**DOC-03 更新与移除**

同一知识库内相同内容重复上传时提示已存在；相同名称但内容不同的文件提示按新版本处理。新版本处理完成后替换旧版本参与后续检索，失败时保留旧版本。

移除文档后不再参与新任务检索。历史回答保留当时的引用片段和版本快照，并标记来源已更新或移除；第一版不提供作为合规删除保证的历史内容彻底清除功能。

### 5.5 对话与会话

**CHAT-01 提问与追问**

支持新建会话、多轮追问、查看历史和删除自己的会话。追问继承当前会话中的已明确条件；对相对日期应转换并展示实际日期范围。对话标题可从首问生成，失败不影响问答。

每个会话同一时刻只执行一个任务，运行期间禁用重复发送。请求去重，刷新页面不重复触发查询。

**CHAT-02 任务状态**

状态包括：待执行、运行中、待澄清、已完成、无匹配数据、证据不足、失败、已停止、已超时。澄清回答作为后续消息继续处理。刷新页面后可恢复读取状态和已保存步骤；第一版不要求服务重启后自动续跑，但需把中断任务标记为失败，不能一直显示运行中。

支持停止当前任务。停止后不再发起新的模型及数据查询，尽力取消在途请求；无法立即取消时提示取消处理中，最终不把局部输出标成完整成功。

**CHAT-03 答案规范**

答案包括：直接结论、必要明细或统计、业务口径及时间范围、来源引用、影响结论的限制。事实性数字应来自实际查询或可验证的计算。引用必须能关联到当前任务的证据。

文档与查询返回内容视为数据，不作为修改系统规则或访问权限的指令。检索结果没有支持答案时明确说明证据不足；查询未返回记录时说明无匹配数据；执行失败时说明失败，不以模型常识补写业务结果。

### 5.6 执行过程展示

**TRACE-01 可见阶段**

按实际发生顺序展示：问题和已确认条件、选定的数据源、查询或检索执行、证据概况、结论生成。每个步骤记录状态、开始时间、耗时和必要的失败原因。

数据库步骤展示实际执行的 SQL 及安全处理后的参数；ES 步骤展示实际 DSL；文档步骤展示检索词、引用文档及相关片段。每次修正查询均保留记录，不能用事后生成的说明冒充实际执行事件。

默认折叠技术细节，用户可展开查看。认证凭证、内部堆栈不展示。此功能展示可审计的执行过程和依据，不承诺展示模型内部完整思维链。

### 5.7 结果下载

**EXPORT-01 报告**

已完成、无匹配数据、证据不足的任务支持下载 Markdown 报告。报告包含问题、最终状态、模型及数据源名称、执行时间、结论、业务口径、查询或检索摘要、引用和限制。失败、停止和超时任务不提供完整分析报告下载入口，页面保留已有过程。

**EXPORT-02 数据**

MySQL、ES 任务有结构化结果时支持 UTF-8 CSV 下载。多个结果集分别命名下载，报告标识结论使用了哪些结果集。ES 聚合按结果结构展开为行；文档问答不承诺输出 CSV。

下载使用该次任务保存的结果快照，不重新查询数据，也不重新让模型生成结论。默认 CSV 最多 1,000 行并明确标识截断，页面预览最多 100 行。对可能被表格软件当作公式执行的内容采取转义措施。

## 6. 页面与主要交互

1. 登录页：账号密码登录、错误提示。
2. 问答页：会话列表、模型和数据源选择、消息区、执行步骤区、来源详情、停止与下载操作。
3. 模型管理页：配置列表、编辑表单、连接及能力测试结果、启停操作。
4. 数据源管理页：MySQL / ES 配置、连接测试、授权范围、结构说明、业务口径与刷新操作。
5. 知识库管理页：知识库、嵌入配置、文档列表、上传、处理状态、失败重试、版本与移除操作。
6. 账号管理页：管理员创建、停用账号和重置密码。

没有可用模型或数据源时显示明确的空状态。普通用户被提示联系管理员，管理员可直接进入配置入口。运行失败时保留用户输入和历史内容。

## 7. 运行约束与默认参数

以下为初始可配置默认值，技术方案需要明确参数位置；调整不得隐藏限制或改变答案含义。

- 单次数据库或 ES 查询超时：30 秒。
- 单次模型调用超时：120 秒。
- 单次问答整体超时：180 秒；整体预算优先于单次调用预算。
- 每次问答最多 5 次外部数据查询或检索，其中失败后的查询修正最多 2 次。
- 单次结果集最多保留 1,000 行；页面预览最多 100 行；ES 单次聚合最多返回 100 个桶。
- 文档每次检索默认最多使用 8 个片段；片段长度、分段方式和上下文上限由技术方案确定并记录。
- 单文件 20 MB，单知识库 100 个有效文档。
- 默认全平台最多 5 个运行中的问答任务；超限时明确提示稍后重试，第一版不设置无限等待队列。

查询超时、结果截断、步骤预算耗尽等均需可见。预算耗尽且证据不完整时，输出已获得的证据及限制，标为证据不足，不宣称完成全部分析。

## 8. 非功能需求

### 8.1 安全与隔离

- 登录后访问业务功能；后端验证角色和会话、下载文件归属，不能只依赖前端隐藏按钮。
- 外部数据源使用只读权限，限制授权表或索引；连接凭证加密保存，日志脱敏。
- 仅管理员可以配置外部服务地址；执行请求不能由普通用户通过问题文本改写目标地址、索引或权限范围。
- 部署时明确模型调用的数据流向。选择外部模型会将必要的问题、元数据和检索结果发送给该服务，数据是否允许发送由管理员在发布配置时确认。
- 会话删除后，其消息、执行记录与导出入口不再可访问；后台清理对应持久化内容及临时文件。备份保留策略由部署说明定义，不承诺实时删除备份。

### 8.2 可用性与性能

- 在约定测试环境内，提交问题后 2 秒内展示已受理或明确错误，不要求 2 秒内生成模型答案。
- 支持 5 个并发问答任务的基本稳定性验收；记录模型、硬件、数据量和实际耗时，不把模型服务性能等同于平台性能。
- 模型、数据源、会话、执行记录及结果快照持久化，应用正常重启后历史可查看、结果可下载。
- 文档处理采用后台任务，上传及解析不阻塞问答页面；处理失败可重试。

### 8.3 可观测性

每次问答具有唯一任务标识，关联模型调用、工具执行、耗时、状态及错误。记录模型返回的用量信息（若提供），不据此承诺精确费用统计。面向用户的错误可理解，开发日志保留排障信息但不泄露凭证。

## 9. 核心数据与一致性

产品需保存以下对象，具体表结构由技术设计确定：

- 用户及角色。
- 模型配置、能力测试记录、配置版本。
- 数据源配置、授权范围、元数据、业务说明和口径版本。
- 知识库、嵌入配置版本、文档版本、分段及来源位置、处理任务。
- 会话、消息、问答任务、执行步骤、证据、结构化结果及导出信息。

每次任务关联所用模型、数据源及业务配置版本。运行中采用配置快照，配置变更影响后续任务；历史报告使用当时的结果与引用，不承诺未来重新执行仍得到相同数据。

敏感凭证不写入面向用户的配置快照。数据源停用后不能继续发起问答，已有历史快照仍可按账号权限访问。

## 10. 验收标准

以下均为第一版发布门槛。测试账号、数据源和数据使用可控的测试环境，真实业务样例须去除不应暴露的信息。

### 10.1 功能验收

- **AC-01 模型：**分别用一个 OpenAI 和一个 Ollama 模型完成配置、测试、启用和问答；错误密钥、不可达地址、不支持工具调用均得到正确状态。停用后无法发起新请求。
- **AC-02 MySQL：**完成筛选查询、分组统计、授权表关联、追问及空结果场景；SQL 可查看，结果与人工基准一致。
- **AC-03 ES：**完成关键词检索、时间过滤、分组聚合及无匹配场景；DSL 可查看，精确及近似统计正确标注。
- **AC-04 文档：**PDF、DOCX、TXT 各完成上传、处理、问答和引用定位；重复上传、版本替换、解析失败与移除规则有效。
- **AC-05 过程：**步骤来自真实执行事件；失败及查询修正可追溯；没有执行成功时不展示虚构成功步骤。
- **AC-06 导出：**Markdown 与页面最终回答、状态、证据一致；CSV 与保存的结果一致，中文可读、截断可见，下载不触发新查询。
- **AC-07 会话：**追问正确继承条件；首问后不能直接换模型或数据源；刷新不重复执行；停止、超时及重启中断有明确终态。
- **AC-08 权限：**普通用户不能维护配置、读取密钥、越权读取其他用户会话或下载文件；数据查询不能写入或突破授权表、索引范围。
- **AC-09 边界：**业务口径不明时先澄清；无数据、证据不足和执行失败分开呈现；文档中的恶意指令不能改变工具权限。
- **AC-10 稳定性：**5 个并发任务下无会话串数据、重复执行或永久运行状态；正常重启后历史与可下载结果保留。

### 10.2 回答质量验收

在功能开发早期建立并固定至少 30 个代表性问题：MySQL、ES、文档各至少 10 个，并覆盖正常查询、聚合或综合回答、追问、无数据或证据不足。另设置不少于 10 个安全及异常用例，不与前述正常业务问题混算。

每个业务问题应有预期结果、业务口径、允许误差（若适用）和依据，由业务负责人确认。正常答案必须同时满足结论正确、口径正确和来源可追溯才算通过。

初始发布门槛：整体业务用例通过率不低于 90%，每类数据源不低于 80%；发布路径的权限、只读约束、会话隔离及不伪造执行证据等关键用例全部通过。每个拟发布模型单独运行测试，不以某一个模型的成绩替代其他模型。不达标的模型不向普通用户启用。

测试结果记录模型实际标识、配置、数据版本、失败问题和复测记录。此门槛衡量约定场景，不等于对所有自然语言问题保证同等准确率。
