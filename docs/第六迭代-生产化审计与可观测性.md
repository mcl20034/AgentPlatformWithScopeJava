# 第六迭代：生产化、审计与可观测性

## 已实现范围

- 所有 API 响应携带 `X-Request-ID`，服务端日志通过 MDC 关联请求。
- 所有已认证的变更请求自动写入操作审计，记录操作者、结果、来源 IP、请求 ID、HTTP 状态和耗时，不记录请求正文或密钥。
- 每次模型调用记录用途、提供商、模型、成功状态、耗时和 Token 用量；同时发布 Micrometer 计数器和计时器。
- 管理员“运行与审计”页面展示最近 24 小时任务、模型调用、依赖状态和操作审计。
- 问答入口支持每用户并发任务和小时提交量限制。
- Actuator 暴露 `health`、`info` 和 `metrics`；健康检查公开，其他端点仅管理员可访问。
- 应用日志默认写入 `./logs/agent-platform.log`，按 20 MB 滚动、保留 30 个历史文件且总量不超过 1 GB。

## 可配置环境变量

- `PLATFORM_MAX_ACTIVE_TASKS_PER_USER`：单用户并发任务上限，默认 2。
- `PLATFORM_MAX_TASKS_PER_HOUR_PER_USER`：单用户每小时任务上限，默认 60。
- `PLATFORM_LOG_FILE`：日志文件路径。
- `PLATFORM_LOG_MAX_SIZE`：单日志文件上限，默认 20MB。
- `PLATFORM_LOG_MAX_HISTORY`：历史文件数量，默认 30。
- `PLATFORM_LOG_TOTAL_SIZE`：日志总容量上限，默认 1GB。

## 手动验收

1. 重启后端，确认 Flyway 自动执行 V7。
2. 用管理员登录，进入“运行与审计”，确认依赖状态和历史任务可见。
3. 发起一次问答，刷新运维页，确认任务与模型调用新增记录。
4. 修改任意管理配置，确认操作审计出现同一响应头中的请求 ID。
5. 检查 `logs/agent-platform.log`，确认日志正常写入且不包含数据源密码或模型密钥。
6. 使用普通用户访问 `/api/v1/admin/operations/summary` 或 `/actuator/metrics`，应返回 403。
