# 第七迭代：部署交付与运行保障

## 1. 交付结构

生产环境采用不可变版本目录和共享数据目录：

```text
/opt/agent-platform/                 C:\ProgramData\AgentPlatform\
  releases/<version>/                 releases\<version>\
  current -> releases/<version>       current -> releases\<version>
  （共享目录位于 /var/lib、/var/log）   data\ logs\ secure\ config\
```

发布包包含后端 JAR、前端静态文件、部署模板和本说明。上传文档、日志、配置和密钥不放进版本目录，因此升级与回滚不会覆盖运行数据。

## 2. 生产前置条件

- Java 21、PostgreSQL 15+、Node.js 22（仅构建机需要）、Nginx。
- 平台数据库使用独立账号和独立数据库。应用账号需要该数据库 schema 的建表、迁移和读写权限，但不应是 PostgreSQL 超级用户。
- 如需在数据库中使用 pgvector，由数据库管理员预先执行 `CREATE EXTENSION vector`。
- 模型、MySQL、Elasticsearch 主机必须加入 `PLATFORM_ALLOWED_OUTBOUND_HOSTS`。
- 后端只监听 `127.0.0.1:8080`，外部流量统一经过 HTTPS 反向代理。

首次部署前生成两个独立文件：管理员临时密码和 32 字节 Base64 主密钥。主密钥丢失后，数据库中已有模型和数据源凭证无法解密。

Linux：

```bash
umask 077
openssl rand -base64 32 > /etc/agent-platform/secure/master-key.txt
openssl rand -base64 24 > /etc/agent-platform/secure/admin-password.txt
chown root:agent-platform /etc/agent-platform/secure/*.txt
chmod 640 /etc/agent-platform/secure/*.txt
```

Windows：

```powershell
$root='C:\ProgramData\AgentPlatform\secure'
New-Item -ItemType Directory -Force $root | Out-Null
$keyBytes=New-Object byte[] 32
$passwordBytes=New-Object byte[] 24
[Security.Cryptography.RandomNumberGenerator]::Fill($keyBytes)
[Security.Cryptography.RandomNumberGenerator]::Fill($passwordBytes)
[Convert]::ToBase64String($keyBytes) | Set-Content -NoNewline "$root\master-key.txt"
[Convert]::ToBase64String($passwordBytes) | Set-Content -NoNewline "$root\admin-password.txt"
```

随后限制 `C:\ProgramData\AgentPlatform` 的 ACL，只允许管理员和服务账号读取。

## 3. 构建发布包

Windows 构建机：

```powershell
$env:JAVA_HOME='D:\develop\jdk\openjdk-21.0.1'
$env:MAVEN_HOME='D:\develop\apache-maven-3.9.8'
.\deploy\build-release.ps1 -Version 0.7.0
```

Linux 构建机：

```bash
bash deploy/build-release.sh 0.7.0
```

脚本默认执行后端测试、`npm ci` 和前端生产构建，输出到 `release/agent-platform-<version>`，并生成后端 JAR 的 SHA-256。正式发布不要使用 `-SkipTests` 或 `-SkipInstall`；本地 Vite 服务占用 `esbuild.exe` 时，应先停止开发服务再构建正式包。

## 4. Linux 安装

1. 将发布目录上传至服务器。
2. 运行 `sudo bash deploy/linux/install.sh /path/to/agent-platform-0.7.0`。
3. 首次安装编辑 `/etc/agent-platform/agent-platform.env`，生成密钥文件，再次运行安装脚本时应使用新的版本号；也可配置完成后直接执行 `systemctl restart agent-platform`。
4. 安装 Nginx 配置，替换域名和证书路径：

```bash
sudo cp deploy/nginx/agent-platform.conf /etc/nginx/conf.d/agent-platform.conf
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl status agent-platform
curl --fail http://127.0.0.1:8080/actuator/health
```

systemd 单元启用了自动重启、只读系统目录、私有临时目录和写目录白名单。

## 5. Windows 安装

Windows 服务使用 WinSW。将对应平台的 WinSW 可执行文件保存为：

```text
C:\ProgramData\AgentPlatform\service\AgentPlatform.exe
```

以管理员身份运行：

```powershell
.\deploy\windows\install-service.ps1 -ReleaseDirectory .\release\agent-platform-0.7.0
```

首次运行会生成 `C:\ProgramData\AgentPlatform\config\agent-platform.env`。填写配置并创建密钥文件后重新运行服务：

```powershell
C:\ProgramData\AgentPlatform\service\AgentPlatform.exe restart
Get-Service AgentPlatform
Invoke-RestMethod http://127.0.0.1:8080/actuator/health
```

Nginx for Windows 可使用同一配置思路，把 `root` 改为 `C:/ProgramData/AgentPlatform/current/frontend`。生产环境更推荐 Linux Nginx 或现有企业网关代理 Windows 后端。

## 6. 升级、健康检查与回滚

升级前必须执行备份并验证发布包哈希。安装脚本仅添加新版本并切换 `current`，不会修改旧版本。

```bash
sudo systemctl status agent-platform
curl --fail https://platform.example.com/actuator/health
journalctl -u agent-platform -n 100 --no-pager
```

应用文件回滚：

```bash
sudo bash deploy/linux/rollback.sh 0.6.0
```

```powershell
.\deploy\windows\rollback.ps1 -Version 0.6.0
```

Flyway 迁移是前向迁移。只有当旧版应用兼容当前数据库结构时才能直接切换应用版本；不兼容时，应停机后将数据库和文档存储一并恢复到升级前备份。

## 7. 备份与恢复

备份必须同时包含 PostgreSQL 与 `PLATFORM_STORAGE_ROOT`，密钥文件单独离线保管。推荐每日备份、至少保留 7 个日备份和 4 个周备份。

```powershell
.\deploy\backup\backup.ps1 -Destination D:\backups\agent-platform
```

```bash
sudo bash deploy/backup/backup.sh /srv/backups/agent-platform
```

每月至少进行一次恢复演练。恢复目标应为空数据库：

```powershell
.\deploy\backup\restore.ps1 -BackupDirectory D:\backups\agent-platform\agent-platform-20260924-120000 -EnvironmentFile C:\ProgramData\AgentPlatform\config\agent-platform.env -Confirm
```

恢复完成后检查 Flyway、管理员登录、数据源解密、知识库文档和一次完整问答。数据库备份与主密钥不可只保存于同一设备。

## 8. 发布验收与故障处理

发布必须依次验证：

1. `/actuator/health` 返回 `UP`，后端端口没有对外网开放。
2. HTTPS、Secure Cookie、登录、首次改密和退出正常。
3. MySQL、Elasticsearch、知识库及组合问答各执行一次。
4. 任务取消、刷新恢复、CSV/Markdown 导出正常。
5. 管理员可查看任务、模型调用与审计；普通用户访问管理接口返回 403。
6. 日志中无数据库密码、模型密钥和主密钥。
7. 备份任务成功，SHA-256 校验通过。

常见故障入口：Linux 使用 `journalctl -u agent-platform` 和应用日志；Windows 使用 WinSW service log、应用日志及 Windows 事件查看器。数据库迁移失败时不要反复重启，应保留现场日志，修复数据库状态后再启动。
